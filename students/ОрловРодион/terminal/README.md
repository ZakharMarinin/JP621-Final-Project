# Подземелье

Консольная текстовая игра на Python 3.10+.
Игрок ходит по комнатам, собирает предметы, говорит с НПС и сражается с врагами
Мир описан в data/world.json, а прогресс сохраняется в data/save1.json.


## Запуск

В репозитории будет .bat файл для запуска

python main.py --new-game
python main.py --load data/save1.json

Сторонние библиотеки не нужны.

## Команды

look — осмотреть комнатуу
go <направление> — перейти (north, south, east, west)
inventory — показать инвентарь
take <item_id> — взять предмет
use <item_id> — использовать предмет
talk <npc> — поговорить с NPC
attack <enemy> — начать бой
save — сохранить игру
quit — выйти

В бою a — атаковать, f — попытаться сбежать

В library есть переходы на юг, запад и север. В hall — на юг и восток. Убить Дракона в throne_room = победа

## Содержимое мира

Комнаты (6): entrance, hall, armory, crypt, library, throne_room.

Предметы (5):
rusty_key (key) — открывает дверь в armory
health_potion (potion) — +30 хп
big_potion (potion) — +60 хп
iron_sword (weapon) — +6 к урону
magic_scroll (weapon) — +4 к урону

Враги (3):
Гоблин — HP 20, урон 4 (иногда бьёт в два раза сильнее)
Скелет — HP 30, урон 6
Дракон — HP 80, урон 12

NPC (2): Старый страж (подсказки), Библиотекарь (даёт свиток).

## Про __init__.py

В models/ и engine/ есть пустые __init__.py — они делают папки
пайтон пакетами чтобы импорты (from models.character import Player)
работали нормально, независимо от версии пайтон и от того
откуда запущена игра

Мне друг в этом немного помог, он больше меня пайтон изучает

## Структура проекта


terminal/
    main.py
    models/       — character.py, item.py, room.py
    engine/       — world_loader.py, save_manager.py, combat.py
    data/         — world.json, save1.json
    README.md

world.json (контент) и save1.json (прогресс) разделены специально:
контент только читается движком, прогресс пишется и читается отдельно.
За это отвечают классы WorldLoader и SaveManager.

## Как устроен код

Есть общий класс Character — «шаблон персонажа» он требует
чтобы у любого персонажа были методы attack() и is_alive().
Конкретно кто как атакует решают классы наследники.

HP спрятаны в _hp. Снаружи доступ только через @property.
Сеттер не даёт уйти в минус или превысить максимум.

Player, Enemy, NPC — это персонажи. Goblin и Skeleton —
частные виды врагов. Potion, Weapon, Key — виды предметов.
Каждый берёт общее поведение у родителя и добавляет своё

В бою вызывается attack() — у каждого свой. Гоблин бьёт с шансом
крита, скелет — обычным ударом. То же с предметами use(player)
вызывается одинаково, но зелье лечит, меч усиливает, ключ открывает.

## Ошибки

Все команды обёрнуты в try/except в игровом цикле
Некорректные направления, отсутствующие предметы, попытка атаковать
пустую комнату — дают понятное сообщение, игра не падает.
Повреждённый JSON тоже приводит к сообщению, а не к traceback.

## Ограничения

Бой простой: только атака и попытка бегства, без магии и способностей или еще чего-то
Диалоги NPC линейные без множества веток диалога
Один слот сохранения
